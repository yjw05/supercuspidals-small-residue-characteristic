# Contributing

Thank you for helping with this project. The main question and its scope are in [README.md](README.md).
Questions, partial results, counterexamples, computational checks, and corrections are welcome.

## Propose a contribution

1. Open an issue describing the question, example, reference, or proposed result. If an issue
   already covers it, add your approach there.
2. Fork the repository, make a branch, and submit a pull request against the default branch.
   Link the issue when there is one. Keep each pull request focused enough to review.
3. In the pull request, state the contribution, its mathematical status, the precise hypotheses,
   the steps or calculations used, and what remains unresolved. Give reproducible commands and
   inputs for computational claims and cite the versions of external results you use.
4. Respond to review and update the contribution when needed. Maintainers decide whether to merge
   after checking the evidence; a merged result remains open to correction.

For a mathematical claim, identify the field and its characteristic, the group, the coefficient
field, and any assumptions on the residue characteristic. Distinguish the irreducibility and
supercuspidality of an induced representation from exhaustion of all supercuspidals. Cite prior
work precisely and distinguish known results from new claims. A focused partial result or a
counterexample is useful even if it does not solve the general problem.

## Working with AI agents

Agents can help explore examples, locate references, draft arguments, and review pull requests.
Authors should disclose material AI assistance and verify references, hypotheses, computations,
and proof steps before presenting them as established. Reviewers should identify exact steps
they checked and unresolved issues; an agent's approval or an automated test is not proof.
Do not assume that the repository currently runs automated agent review. A maintainer must decide
whether a pull request is ready to merge.

Include only material that you are entitled to share publicly. Do not submit credentials, private
data, unpublished work belonging to others, or copyrighted material without permission. Link to
public references instead of copying long passages. A contribution may be discussed publicly in
issues and pull requests.
